## 一、语境联想（Context-Aware Suggestion）

### 1. 定位与铁律
- 目标：文本框已有内容（如"明天"）时，联想提供语义相关候选（明天早上/明天开会/明天见）
- **铁律：严禁造词**——候选 100% 来自既有词库（云端词组表 + 本地高频词），系统只"召回+排序"，绝不"生成"

### 2. 四层流程
```
输入: 文本框现有文本 T（光标前最后 1-3 个完整词/短句）
  ↓ ① 边界识别: 按标点/空格/换行切分；中文用轻量分词（双数组 Trie 最大匹配，端侧毫秒级）
  ↓ ② 场景归类: 命中场景词库打标签
      时间词(明天/今天/几点)→时间场景 | 地点词(深圳/公司)→地点场景
      动词(开会/吃饭/去)→动作场景 | 问候(你好/谢谢)→社交场景
      （端侧固化 ~200 场景词，云端可扩展）
  ↓ ③ 联想召回（只召回不生成）:
      a. 前缀召回: 云端词组表"首词=T"倒排索引（"明天"→明天早上/明天下午/明天见…）
      b. 场景召回: 场景标签 → 场景短语表（既有短语，模板不动态拼接造词）
  ↓ ④ 排序: 词频 > 最近上屏 > 场景匹配度 > 码长（与现有候选排序规则统一）
```

### 3. 数据结构
- 端侧: context_map.json（场景词→标签 ~200 条）
- 云端: context_phrases.json（前缀→候选列表，**由既有词组表离线生成倒排索引，本身零新词**）

### 4. 严禁造词三重保障
1. 候选集合 = 既有词库严格子集（只有召回逻辑，无生成逻辑）
2. 每次联想结果做词库存在性校验（候选必须能在词组表 grep 到）
3. 场景模板只选既有短语，不做词素拼接

## 二、英文翻译（Translate）

### 1. 场景
- 选中文本或当前候选 → 点翻译键 → 中译英（可扩展英译中）
- 免费实现：端侧词典 + 云端百度翻译 API 兜底

### 2. 流程
```
输入: 文本 S
  ↓ ① 长度判定: ≤2 字→端侧词典（复用已有 en_dict.json ~5000 词）；>2 字→云端 API
  ↓ ② 云端翻译: 百度翻译开放平台 /api/trans/vip/translate（q/from/to/appid+MD5sign，免费额度）
  ↓ ③ 降级: API 超时/失败 → 端侧逐词翻译拼接 + 标注"机翻"
  ↓ ④ 展示: 结果插候选栏最右（🌐 图标），点选即上屏
```

### 3. 性能与成本
- 联想召回端侧毫秒级（Trie 索引）；云端仅翻译 >2 字时调用，免费额度内零成本
- 百度翻译密钥：已有（历史提供，可用）

---

## 三、与云五笔体系兼容
1. 联想/翻译候选只占"候选栏扩展位"，**不影响主候选排序规则**（最近上屏>高频>二字>三字>四字）
2. 设置页开关可关（默认状态待定）
3. 联想触发：候选栏空时 + 文本框有内容时自动显示；有编码时不干扰

## 四、与 TRAE 交换要点（求同存异）
| 议题 | 豆包方案 | 待 TRAE 补充/质疑 |
|---|---|---|
| 造词红线 | 召回制（索引从既有词库生成）| 有无更严校验法 |
| 分词 | 端侧 Trie 最大匹配 | 有无更轻方案（词频表+双向匹配）|
| 场景识别 | 场景词库打标签 | 是否需要统计式场景（N-gram）|
| 翻译降级 | 端侧逐词+机翻标注 | 是否要整句缓存 |
| 触发时机 | 候选空+文本有内容 | 是否要输入停顿检测（如 500ms）|
