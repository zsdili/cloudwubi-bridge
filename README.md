# 云五笔 AI 协作信箱（CloudWubi Bridge）

## 协作共识（CONSENSUS — 豆包 ⇄ TRAE 共同遵守）

### 一、分工原则
- **豆包主导**：算法设计、词库与验收标准、任务派发、核验结论
- **TRAE 配合**：编译构建、真机/模拟器操作、截图取证、执行回报
- **用户把控**：提出要求、意见与建议，最终验收

### 二、FSABE 方法论（每轮任务、每次回报必须按此结构）
- **F（事实）**：只陈述客观、可验证的事实（做了什么、测得什么、报错什么），**严禁掺入假设或主观判断**——F 错则全盘错
- **A（分析）**：基于 F 的深入分析，只分析与本任务相关的部分；穷举"做/不做/做好/做坏"的后果
- **B（结论）**：用二元判断词（好/坏、多/少、快/慢、盈/亏、活/灭）给出明确结论，并说明对用户和产品的影响
- **E（方案）**：解决方案+落地执行步骤，给出 2-3 个定向选项（末项"或其他"）供用户选择

### 三、永续推进原则
- 任务编号**全局递增**（T1、T2、T3…），回报必须注明对应任务号
- 完成回报 → 豆包轮询核验 → 写下一项任务，**循环不停**
- E 方案用户选定后**立即推进**，不因等待而停止

## 双向规则
1. **豆包 → TRAE**：向 `inbox.md` 追加任务（`## 任务 T{n} {日期}` + 要求 + 验收标准）
2. **TRAE → 豆包**：完成后在 `outbox.md` 追加回报（`## 回报 T{n}` + FSABE 结构 + 截图/证据 + 遗留）
3. **时序**：TRAE 开工前 `git pull` 读 inbox；完成后 `git push` outbox；豆包每 15 分钟自动轮询
4. **界面截图**：TRAE 放项目内 `team-handoff/` 或报告公开可访问链接
